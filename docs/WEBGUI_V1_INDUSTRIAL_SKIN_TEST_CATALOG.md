# ECU Platform V2 — WebGUI V1 industrial skin on the TESTS catalog

Status: candidate only on branch webgui/test-catalog-v1-industrial-skin,
stacked on webgui/test-catalog-daf-sac-v1 (legacy-layout PR #22).
Do not merge to main, do not autodeploy.

## Design decision

Preserve the approved navigation and information architecture from the
legacy-layout work but use the already accepted WebGUI V1 visual system,
not the bright-blue Qt/QML aesthetic. The source of truth is the V1
home view and the root WebGUI CSS tokens:

- Background #f1f3f6, topbar #e5eaf0, panel #f7f8fa.
- Text #182536 and secondary labels #606e7b.
- Fine borders #b2bfcb, rules #c5ced8, blue accent #226da8,
  restrained top stroke #668eb4.
- Flat rectangular tiles, radius 2px, no bright filled QML controls,
  gradients or complicated animations.
- Preserve the V1 topbar, hidden kiosk mouse cursor, home screen,
  language controls and operator bearer authentication.

## Exact information architecture

TESTS -> TRUCK / AGRI / OHV.
TRUCK -> MAN / DAF / SCANIA / IVECO / MB.
DAF -> SAC.

SAC -> four parameter rows in one V1 flat panel:
Pressure 1, Pressure 2, Battery Permanent, Battery Ignition.
Contextual left MENU -> DTC / Activations / Programming.

DTC -> historical completed readout with three table columns:
code / explicitly unverified description / raw status byte, plus a
read-only details dialog. AGRI/OHV and other manufacturer pages
show explicit placeholders; they do not claim DUT support.

The old Qt/QML source was used solely to recover the arrangement;
see WEBGUI_TEST_CATALOG_DAF_SAC_LEGACY_REFERENCE.md. No old
CockpitController calls, DTC erase, automatic speed search,
CAN reset or direct hardware access is carried forward.

## Security and data quality

- No API, Bench Runtime, DUT Profile or CORE changes.
- No CAN TX, PF_CAN, privileged Bench Agent socket, serial/USB,
  power control or any other physical operation from browser code.
- Existing authenticated GET-only Application API V1; browser bearer
  credential remains private and time-limited in page memory.
- All four SAC measurements display em dash until a verified
  application-owned parameter readout and API DTO are available.
  Prior FE96 readings are not live values; FE/FF pressures mean
  unavailable, not zero.
- Completed DTC is historical, freshness-checked and accepted for SAC
  only if the profile matches and the protocol is UDS. Invalid,
  expired or other-profile readouts are not displayed as SAC data.
- Activations and Programming remain explicitly unavailable until
  separately reviewed backend admission and safety interlocks exist.

## Operator-only deployment after approval

Interactive VS Code terminal on CM5:

    cd ~/ECU_WebGUI_V1_SKIN
    sudo bash scripts/deploy_cm5_webgui_v1_skin.sh

Installer checks root/TTY, expected clean Git branch, kiosk/API/Bench
services active, CAN DOWN, tokenless API refusal, and an unused release
path. It stages immutable root-owned WebGUI assets, verifies the V1
CSS/markup, HTTP/CSP and health checks, and restarts only WebGUI
static server + kiosk. A post-install failure triggers a scoped
rollback preserving the previous release and readout state.

Recovery after this release is installed:

    sudo /usr/local/sbin/ecu-webgui-v1-skin-rollback

Physical display/touch and reboot must be accepted separately.
No PR, green CI or candidate build is authority to auto-deploy or
merge to production main.
